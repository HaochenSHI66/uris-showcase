🎯 项目定位

URIS 是一个面向 家居场景多轮视觉指代消解 的研究项目。我们识别出当前 SOTA VLM 的一个被忽视的失败模式：不是看不见物体，而是在歧义和时序上下判断太早（over-commit）。

论文主线：用 DomesticGround benchmark 揭示这个失败，用 EAP（Evidence Acquisition Policy）缓解它，跨多个 frozen VLM backbone 验证有效性。

项目以 Benchmark-first 为论文核心载体：5,000 条 × 8 维诊断评估，scene-disjoint split，含 human upper bound。Method 部分提出一个 3M 参数的轻量 policy（5 actions），在 AI2-THOR 真交互环境主评估。所有数据 100% 来自公开数据集（Hypersim / HOI4D / AI2-THOR），无需 IRB 审批。

🎓 URIS 论文的 6 个理论概念骨架：
  1. Active perception（Bajcsy 1988 → Embodied VideoAgent ICCV'25）— 给 ZOOM/CLARIFY action 提供 38 年理论传承
  2. Structured visual grounding（Shikra → GLaMM → Ferret-v2）— 把 ANSWER 框成 REC 而非 free-form VQA
  3. Conversational disambiguation（OpenEQA → Talk2Car 谱系）— frame CLARIFY action 的合法性
  4. Hallucination as over-commitment（POPE → HallusionBench → OPA-DPO）— 论证 WAIT/REJECT 不是工程 trick
  5. Group Relative Policy Optimization（DeepSeek-R1 → Visual-RFT → VLM-R1）— frame Stage 3 训练
  6. Mixture-of-Experts efficient tuning（Qwen3-VL-30B-A3B = 3B activated）— frame "30B 模型可在中等算力下 fine-tune" 的合理性

③ 三大 Contribution 设计

每条对应具体实验、表格、章节
One-line Research Question：
"Do current VLMs fail at multi-turn domestic grounding because they cannot see, or because they over-commit under ambiguity—and can a lightweight evidence acquisition policy close the gap without retraining the VLM?"
#Contribution对应实验论文位置
C1 DomesticGround Benchmark：诊断型 benchmark for 2D 家居 reference resolution，5,000 queries × 8 维度（含 Abstention），scene-disjoint split（train/val/test = 3,000/700/1,300），含 explicit AMBIGUOUS / SYSTEM_UNSUPPORTED 标签 + paired hallucination control + human upper bound。措辞避开 "first multi-turn"（InViG/SAMA 已占位），改为 "jointly evaluates domestic clutter × multi-turn carry-over × abstention × hallucination" 15 baseline × 8 维 × 3 metrics + Fleiss κ ≥ 0.65 IAA §3 Benchmark + Table 1, 2
C2 Systematic findings：通过 15 个 VLM 在 5,000 条上的零样本评估，测试 3 个核心假设：
H1：single-turn grounding performance does not predict multi-turn carry-over robustness
H2：a substantial fraction of hallucinations come from over-commitment under ambiguity
H3：clarification ability is weakly correlated with standard grounding accuracy
实验跑完后填具体数字，论文写作时用断言而非假设		 15 baseline × 8 维 × 失败模式诊断 §4 Findings + Table 2, 3 + Figure 3
C3 EAP — Evidence Acquisition Policy：3M-param 轻量 policy，5 actions（ANSWER / ZOOM / WAIT / CLARIFY / REJECT）真正改变可用证据（不是裁 crop）：ZOOM = AI2-THOR 物理移动 + 1080p 重拍；WAIT = THOR advance simulator；CLARIFY = template-based user simulator（主表），LLM-as-user 仅 robustness setting，oracle 仅 upper bound。Backbone-agnostic 通过 candidate proposal adapter 统一接口（cross-backbone calibration ablation 验证），跨 Qwen2.5-VL / LLaVA-OV / InternVL3 三个 frozen backbone AI2-THOR 300 episode 主结果 + 多 backbone 验证 + cost-accuracy Pareto frontier §5 EAP + Figure 4-6

④ 数据挑选最终方案

100% 公开数据集 · 无 IRB / 无 PII 麻烦 · 总下载约 350GB
为什么用 HOI4D 而非 Ego4D：Ego4D 的 NLQ/MQ 任务只标注时间窗口（zero bbox），VQ/EgoTracks 有 bbox 但 query 是图像不是语言。要算 Acc@IoU=0.5 必须有逐帧 bbox + 语言 query，HOI4D（610 室内场景，逐帧 bbox 现成）是家居视频源中唯一同时满足这两个条件的。Ego4D Goal-Step 仅做 time-window IoU 评估辅助。
挑选哲学：不要把所有可能的数据源都堆进去——那样下载、清洗、跨数据集对齐都是负担。原则是每个维度只选一个最适合的，最后收敛到 3 张主牌：Hypersim + HOI4D + AI2-THOR，加 Ego4D Goal-Step / RefCOCO / LLaVA 作辅助。

⑤ 三阶段微调（定位为 strong baseline recipe）

基于 Visual-RFT [13] / VLM-R1 [14] / Reason-RFT [15] 范式 · 不再当 contribution
定位说明：Visual-RFT / VLM-R1 / Reason-RFT 已经把 SFT + GRPO 这条路铺得很深，URIS 的三阶段微调 定位为 strong baseline recipe（论文 §4.2），向社区贡献一个 reproducible recipe，不作为主 contribution。主 contribution 是 Findings（见 §3）。

📐 三阶段详细设计

Stage 1: Grounding Warmup（让模型学会 box 输出格式）

数据RefCOCO/+/g 改写为 Qwen3-VL 原生格式 50K，box 用 [0,1000] 整数
目标强制学输出 <|object_ref_start|>X<|object_ref_end|><|box_start|>(x,y),(x,y)<|box_end|>
配置DoRA r=128, α=256, freeze vit, LR=1e-4, 1 epoch, cosine schedule
时长8×A800 约 8 小时
验收RefCOCOg val Acc@0.5 ≥ 85%

Stage 2: Domain SFT（DomesticGround 领域适应）

数据DomesticGround train + Stage 1 数据 1:1 mix + HOI4D multi-frame + LLaVA replay（合计 36,750 条）
目标领域适应 + 多轮对话 + 时序记忆
配置接 Stage 1 ckpt 续训, LR=5e-5, 3 epochs, share-expert LoRA + LoRA+ ratio=16
关键 trickBox token loss 加权 2.0 + 30% 样本带 CoT reasoning（用 Qwen3-VL-235B 蒸馏生成）
时长8×A800 约 16 小时
验收DomesticGround val Acc@0.5 ≥ 75%

Stage 3: GRPO Refinement（RL 精修，按 VLM-R1 / Visual-RFT）

数据对每个 query 用 Stage 2 模型采样 G=8 个 candidate，IoU 作 reward
目标提升精度 + OOD 泛化（Visual-RFT 报告 +21.9%）
Reward0.9 × IoU(pred, gt) + 0.1 × format_correct
配置GRPO group=8, KL β=0.04, LR=1e-6, 5K RL steps
防 reward hacking双 reward + KL 约束 + 输出长度限制 1024 + 每 100 step 跑 RefCOCOg val 监控
时长8×A800 约 24 小时
验收RefCOCOg val Acc@0.5 ≥ 90% (+5pp vs Stage 2)

⑥ EAP — Evidence Acquisition Policy

不再叫 "Active Perception Policy" · 真正改变可用证据 · 跨 backbone · cost-accuracy 量化
设计核心：EAP 不是单纯的 decision head，而是真正的 active perception——主评估搬到 AI2-THOR 真交互环境（ZOOM = 物理移动 + 1080p 重拍，WAIT = THOR advance simulator）。区别于 Active-O3 (2505.21457) 仅静态图 + 单 ZOOM 动作，URIS 三大设计：① AI2-THOR 真交互（不是裁 crop） ② Backbone-agnostic（state 不送 visual feature，跨 3 个 frozen VLM） ③ cost-accuracy Pareto 量化（4 个新指标）。

🧠 EAP Policy 设计（backbone-agnostic state）

# State s_t (14 维 confidence/几何/历史向量，不送 visual feature)
s_t = [
    top_k_confidence (k=5),          # VLM top-5 候选 prob
    bbox_geometry (k=5, 4-d each),   # 候选 bbox 归一化坐标
    candidate_set_size,              # 候选数
    entropy,                          # top-k 分布熵
    history_actions (K=5, one-hot),  # 历史动作
    step_index,                       # 当前步数
    last_action_outcome              # 上一步 reward
]

# Policy π_θ: 2-layer MLP（不再 Transformer，~3M params）
# 5 actions 真正改变可用证据(AI2-THOR 实际执行):
a1: ANSWER             # 提交当前 top-1 候选
a2: ZOOM(bbox_i)       # THOR 物理移动 + 1080p 重拍(不是 crop)
a3: WAIT               # THOR advance simulator，等物体重现/视角变化
a4: CLARIFY(attr)      # template-based user simulator (主表), LLM-as-user/oracle 仅 robustness/upper bound
a5: REJECT             # 拒答(abstention)

🌍 主评估场景：AI2-THOR 300 episode

环境AI2-THOR iTHOR + ProcTHOR-10K，120 个室内场景
Episode 设置每 episode 10 物体，3-5 个同类干扰物，每物体随机 query
ZOOM 实现controller.step('Teleport', position=...) + 高分辨率重拍
WAIT 实现controller.step('Pass') × N 步，环境物体可能移动
CLARIFY 三档主表：Template-based User Simulator（基于已标注属性回答颜色/位置/大小，可复现，无 LLM 不稳定性）
Robustness setting：LLM-as-user（GPT-4o 扮演用户，验证 EAP 对回答风格变化的鲁棒性）
Supplementary：Prolific human study 300 query 验证 template 的有效性
Upper bound only：Templated Oracle（仅放 appendix）
Success criterion最终 ANSWER 的 bbox IoU ≥ 0.5 vs ground truth

🔄 Backbone-Agnostic 验证

核心挑战：不同 VLM 的 top-k confidence 和候选生成机制不一致，需要 normalize 才能真正实现 plug-and-play。

解决方案：

  • Candidate Proposal Adapter：在每个 backbone 前加一层统一接口，将不同 VLM 的输出 normalize 为 (top-k bbox, score, rank margin, normalized score gap) 标准格式
  • State 用更稳的特征：rank margin / normalized score gap / overlap statistics / detector-side geometry，而非原始 top-k probability（不同模型 calibration 不同）
  • Cross-backbone calibration ablation（必跑）：分别报告 raw confidence vs calibrated 的 EAP 收益

3 个 frozen backbone：

  • Qwen2.5-VL-7B / Qwen3-VL-30B-A3B（主 backbone）
  • LLaVA-OneVision-7B
  • InternVL3-8B

每个 backbone 上汇报 success rate 提升 + hallucination 降低，证明 EAP 真的 plug-and-play。

🎯 Reward 设计（含 cost penalty + hallucination penalty）

# Reward = task_reward − β · cost − γ · hallucination_penalty
ANSWER 正确          → +1
ANSWER 错误          → −1
ZOOM 后 IoU 提升     → +0.3
WAIT 后目标重现     → +0.2
CLARIFY 减少候选    → +0.2 × Δcandidates/total
REJECT (gt 不存在)   → +0.5
REJECT (gt 存在)     → −0.8  # abstention 失误重惩
每步                 → −0.05 × β  # 鼓励效率
hallucinate          → −0.5 × γ  # 惩罚 over-commitment

⑫ 致命风险 + 缓解 + Workshop Fallback

风险 1：标注人力必须匹配 5,000 条目标
三种可执行方案：
方案 A（推荐）：5 人 × 8 周 × 125 条 = 5,000（招够人，留 buffer）
方案 B：3 人 × 12 周 × 140 条 ≈ 5,040（延长到 12 周）

怎么救：① 备好 ¥3,000 应急金，紧急时挂 Prolific 外包 1,500 条 ② 准备 4,000 条"最小版"作 fallback ③ 第 8 周中检不达标立刻切方案 B
风险 2：GRPO 训不出来（中-高）
RL 训练本身就难调（不是 URIS 独有的问题），GRPO 容易遇到 reward hacking、loss 爆炸、router 塌缩这些坑。

怎么救：① 严格照搬 VLM-R1 [14] 的公开代码，别自己魔改 ② Plan B：退到 SFT + DPO 路线，发表难度小一点 ③ 最坏情况：纯 SFT 也行，RefCOCOg 90% 已经是好成绩了 ④ 实在不行就把方法部分削弱，主打 benchmark 章节，照样能成文
风险 3：中期报告留下的"坑"（必须正视）
之前中期报告里 LoRA 那版的数据是基于很小的 pilot 跑出来的，实测在更大数据集上效果不稳定，所以这次必须重训一版。如果论文还直接沿用中期那个 87% 数字而没新数据支撑，reviewer 一查复现就出问题。

怎么救：论文里所有数字必须用新跑的 5,000 条 DomesticGround 重新生成；在 Limitations 里大方写 "早期 LoRA 配置受限于数据规模和训练资源，效果未达预期，本工作通过 SFT + GRPO 三阶段训练 + 公开数据集二次标注解决了这一问题"——把过去的不足转成 motivation，反而能体现项目演进的逻辑性。
风险 4：被同期工作撞车（中）
Active VLM / interactive grounding 这块 2025-2026 是热点，半年里很可能蹦出 2-3 篇类似工作把你的 novelty 抢了。
