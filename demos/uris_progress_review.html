🎓 URIS 论文的 6 个理论概念骨架：
  1. Active perception（Bajcsy 1988 → Embodied VideoAgent ICCV'25）— 给 ZOOM/CLARIFY action 提供 38 年理论传承
  2. Structured visual grounding（Shikra → GLaMM → Ferret-v2）— 把 ANSWER 框成 REC 而非 free-form VQA
  3. Conversational disambiguation（OpenEQA → Talk2Car 谱系）— frame CLARIFY action 的合法性
  4. Hallucination as over-commitment（POPE → HallusionBench → OPA-DPO）— 论证 WAIT/REJECT 不是工程 trick
  5. Group Relative Policy Optimization（DeepSeek-R1 → Visual-RFT → VLM-R1）— frame Stage 3 训练
  6. Mixture-of-Experts efficient tuning（Qwen3-VL-30B-A3B = 3B activated）— frame "30B 模型可在中等算力下 fine-tune" 的合理性

One-line Research Question（v5）：

C1 DomesticGround Benchmark（v5 重写）：诊断型 benchmark for 2D 家居 reference resolution，5,000 queries × 8 维度（含 Abstention），scene-disjoint split（train/val/test = 3,000/700/1,300），含 explicit AMBIGUOUS / SYSTEM_UNSUPPORTED 标签 + paired hallucination control + human upper bound。措辞避开 "first multi-turn"（InViG/SAMA 已占位），改为 "jointly evaluates domestic clutter × multi-turn carry-over × abstention × hallucination" 15 baseline × 8 维 × 3 metrics + Fleiss κ ≥ 0.65 IAA §3 Benchmark + Table 1, 2
C2 Systematic findings（v5 重写）：通过 15 个 VLM 在 5,000 条上的零样本评估，给出 3 条数字断言：(i) 单轮 grounding 强不代表多轮强（carry-over 平均掉 41%）；(ii) hallucination 主要来自 over-commitment under ambiguity（而非感知错误）；(iii) clarification ability 与 grounding accuracy 相关性极弱（Spearman ρ ≈ 0.07） 15 baseline × 8 维 × 失败模式诊断 §4 Findings + Table 2, 3 + Figure 3

④ 数据挑选 v5 最终方案（Ego4D → HOI4D）

100% 公开数据集 · 无 IRB / 无 PII 麻烦 · 总下载约 350GB
v5 关键修改：Ego4D 退到 HOI4D。Reviewer #2 一针见血指出 Ego4D NLQ/MQ 只有时间窗口（zero bbox），VQ/EgoTracks 有 bbox 但 query 是图像不是语言。要算 Acc@IoU=0.5 必须有逐帧 bbox + 语言 query，HOI4D（610 室内场景，逐帧 bbox 现成）是唯一同时满足的家居视频源。Ego4D Goal-Step 仅做 time-window IoU 评估（不算 spatial）。
挑选哲学：不要把所有可能的数据源都堆进去——那样下载、清洗、跨数据集对齐都是负担。原则是每个维度只选一个最适合的，最后收敛到 3 张主牌：Hypersim + HOI4D + AI2-THOR，加 Ego4D Goal-Step / RefCOCO / LLaVA 作辅助。

⑥ EAP — Evidence Acquisition Policy（v5 重设计）

不再叫 "Active Perception Policy" · 真正改变可用证据 · 跨 backbone · cost-accuracy 量化
v5 关键修改（应对 Reviewer #2）：v4 的 Active Policy 只在静态图裁 crop——reviewer 直接说"这只是 decision head，不是真正 active perception"，且与 Active-O3 (2505.21457) 重叠度高。v5 三大重设计：① 主评估搬到 AI2-THOR 真交互（ZOOM = 物理移动 + 1080p 重拍） ② Backbone-agnostic（state 不送 visual feature，跨 3 个 frozen VLM） ③ cost-accuracy Pareto 量化（4 个新指标）。

🧠 EAP Policy 设计（backbone-agnostic state）

# v5 State s_t (14 维 confidence/几何/历史向量，不送 visual feature)
s_t = [
    top_k_confidence (k=5),          # VLM top-5 候选 prob
    bbox_geometry (k=5, 4-d each),   # 候选 bbox 归一化坐标
    candidate_set_size,              # 候选数
    entropy,                          # top-k 分布熵
    history_actions (K=5, one-hot),  # 历史动作
    step_index,                       # 当前步数
    last_action_outcome              # 上一步 reward
]

# Policy π_θ: 2-layer MLP（不再 Transformer，~3M params）
# 5 actions 真正改变可用证据(AI2-THOR 实际执行):
a1: ANSWER             # 提交当前 top-1 候选
a2: ZOOM(bbox_i)       # THOR 物理移动 + 1080p 重拍(不是 crop)
a3: WAIT               # THOR advance simulator，等物体重现/视角变化
a4: CLARIFY(attr)      # 调用 GPT-4o oracle 真正缩小候选集
a5: REJECT             # 拒答(abstention)

🌍 主评估场景：AI2-THOR 300 episode

环境AI2-THOR iTHOR + ProcTHOR-10K，120 个室内场景
Episode 设置每 episode 10 物体，3-5 个同类干扰物，每物体随机 query
ZOOM 实现controller.step('Teleport', position=...) + 高分辨率重拍
WAIT 实现controller.step('Pass') × N 步，环境物体可能移动
CLARIFY 实现GPT-4o oracle 根据 ground truth 给精确 disambiguation hint
Success criterion最终 ANSWER 的 bbox IoU ≥ 0.5 vs ground truth

ANSWER 错误          → −1

⑫ 致命风险 + 缓解 + Workshop Fallback

风险 1：标注做不到 3,500 条（发生概率高）
3 个同学 × 8 周 × 每周 150 条 ≈ 3,600，刚好够。任何一个同学半路掉链子（考试周、找工作、突然忙），或 schema 中途大改要重标，进度立刻就崩了。

怎么救：① 备好 ¥2,000 应急金，紧急时挂 Prolific 外包 1,500 条 ② 提前准备一个 1,500 条的"最小版"作 fallback，至少能投 ③ 第 8 周中检不达标立刻砍 sub-task，不要硬撑
风险 2：GRPO 训不出来（中-高）
RL 训练本身就难调（不是 URIS 独有的问题），GRPO 容易遇到 reward hacking、loss 爆炸、router 塌缩这些坑。

怎么救：① 严格照搬 VLM-R1 [14] 的公开代码，别自己魔改 ② Plan B：退到 SFT + DPO 路线，发表难度小一点 ③ 最坏情况：纯 SFT 也行，RefCOCOg 90% 已经是好成绩了 ④ 实在不行就把方法部分削弱，主打 benchmark 章节，照样能成文
风险 3：中期报告留下的"坑"（必须正视）
之前中期报告里 LoRA 那版的数据是基于很小的 pilot 跑出来的，实测在更大数据集上效果不稳定，所以这次必须重训一版。如果论文还直接沿用中期那个 87% 数字而没新数据支撑，reviewer 一查复现就出问题。

怎么救：论文里所有数字必须用新跑的 3,500 条 DomesticGround 重新生成；在 Limitations 里大方写 "早期 LoRA 配置受限于数据规模和训练资源，效果未达预期，本工作通过 SFT + GRPO 三阶段训练 + 公开数据集二次标注解决了这一问题"——把过去的不足转成 motivation，反而能体现项目演进的逻辑性。
风险 4：被同期工作撞车（中）
Active VLM / interactive grounding 这块 2025-2026 是热点，半年里很可能蹦出 2-3 篇类似工作把你的 novelty 抢了。

怎么救：① 第 17 周 Draft v1 出来立刻挂 arxiv 占坑 ② 主打差异化卖点：geometry-aware policy state（用了 YOLO 的 bbox 几何信息）这点别人没做过 ③ 加 cross-domain 实验（office / outdoor 场景），扩大覆盖面，让审稿人觉得你做的更全
